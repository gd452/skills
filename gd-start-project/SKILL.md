프로젝트 초기 세팅을 수행한다.

## 워크플로우

### 1. 요구사항 파악

- 프롬프트가 있으면 → 파싱하여 부족한 부분만 확인
- 프롬프트가 없으면 → "어떤 프로젝트를 시작하시나요?"
- 파악할 항목: 핵심 기능(what), 기술 선호(how), 대상 사용자(who)
- 답변 못하는 항목은 건너뛰거나 적절한 기본값 추천
- 최소한 "what"만 있으면 진행 가능

### 2. 복잡도 판단

요구사항을 파악한 뒤, 사전에 정해야 할 설계 결정이 많은지 판단한다.

다음 중 해당사항이 많으면 `/gd-write-spec`을 추천:
- 데이터 모델 간 관계가 복잡하거나 엔티티가 다양함
- 화면/산출물이 다양함
- 외부 시스템 연동 필요 (API, DB, 인증 등)
- 요구사항이 모호하여 구조화가 필요

자동 호출하지 않고, 추천만 하고 사용자가 결정한다.

```
→ 분기
  ├─ 간단 → 바로 프로젝트 세팅 (Step 3)
  └─ 복잡 → "/write-spec으로 상세기획을 먼저 하시겠어요?"
       ├─ Yes → Skill("gd-write-spec") 호출 → SPEC.md 생성 → Step 3으로 이어서 진행
       └─ No → 바로 프로젝트 세팅 (Step 3)
```

### 3. 프로젝트 세팅

아래 파일을 생성한다 (이미 있는 파일은 건너뜀):

#### TODO.md
- 서브프로젝트(큰 주제)별 `## 섹션`으로 구분
- 상태 표기: `[x]` 완료 · `[~]` 진행중 · `[ ]` 미착수
- SPEC.md가 있으면 그 내용을 기반으로 TODO 항목 생성
- SPEC.md가 없으면 요구사항 파악 내용을 기반으로 TODO 항목 생성

#### CLAUDE.md에 Session Rules 추가
- 세션 시작 시 TODO.md를 읽고 체크박스 상태를 확인하여 현재 진행 상태를 파악한다.
- 작업 완료 → `[x]`, 진행중 → `[~]`로 TODO.md 갱신한다.

#### MEMORY.md 초기화
- 위치: 프로젝트 루트 `./MEMORY.md` (git 동기화, 멀티 머신 공유)
- 초기 내용: 프로젝트 요약 1~2줄 + 핵심 구조/파일 경로
- 200줄 이내 유지 (초과분은 잘림)

#### README.md 생성
- 프로젝트 소개, 설치, 사용법
- 초기 1회 생성 후 필요 시 갱신

## 문서 역할 (혼재 금지)

| 파일 | 독자 | 역할 | 갱신 |
|------|------|------|------|

| `TODO.md` | Claude Code + 팀원 | 작업 트래커 (체크박스로 진행률 추적) | 매 세션 |

| `MEMORY.md` | Claude Code | 세션 간 컨텍스트 유지 | 매 세션 |
| `README.md` | GitHub 방문자 | 프로젝트 소개 | 필요 시 |
